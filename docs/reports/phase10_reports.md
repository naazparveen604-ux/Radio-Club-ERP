# Phase 10 — Reports Module

## Overview
The V1 Reports Module provides robust, real-time extraction of ERP data in standard formats (CSV and PDF). It leverages the unified client-side RLS enforcement model to guarantee that exported data strictly adheres to the user's operational privileges.

## Implemented Report Types
| Type | Description |
| :--- | :--- |
| **Members & Profiles** | Roster of club members, roles, departments, and join dates. |
| **Attendance Records** | Historical attendance logs filtered by member and date. (Manager/Admin Only) |
| **Tasks & Assignments** | Work progress, priorities, status, and team assignments. |
| **Leave Requests** | Comprehensive historical leave log, reasons, and resolution status. |
| **Programs** | Hosted program events, categorical data, dates, and status. |
| **Events** | General event schedules, locations, and status. |

## Export Capabilities

### 1. CSV Export
- Fully handles commas, quotes, and newlines by injecting dynamic double-quote wrappers using `escapeCSV` logic.
- Prevents structural breaking (e.g. `John, Doe` remains a single column string).
- Immediately processes client-side blob downloading.

### 2. PDF Export
- Utilizes `jspdf` and `jspdf-autotable`.
- Implements strict tabular rendering with professional 10pt headers, timestamp logs, and caller authentication footprints (`Generated by: <email>`).
- Supports automatic multi-page overflows for large datasets.

## Authorization & Security
- **No Edge Function Required**: Because Supabase natively wraps all `select()` requests in PostgREST RLS, a Manager fetching "Tasks" will ONLY receive tasks where `team_id` matches their managed team.
- **Client Integrity**: By keeping generation fully client-side using authorized data payloads, we completely avoid the risk of Edge Function data leaks, OOM crashes for massive datasets, or service-role credential bypasses.

## Known Limitations
- V1 does not offer deep cross-filtering inside the UI (e.g., "Export only Pending Tasks between Jan and March"). It strictly exports the holistic view of the authorized scope.
- CSV output uses raw column dumps without relational unpacking beyond 1-level deep joins (e.g., `role.name` is flattened, but deeper trees are not natively supported in V1 CSV export).
